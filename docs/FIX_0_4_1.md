## Code defects and changes

The catalog query ran on Android's UI thread under1.2s dispatch timeout and sorted
using repeated loadLabel calls. Slow package/resource calls could exceed that
wait and also delay UI/TTS callbacks.0.4.1 moves it to one dedicated background
loader, resolves each retained label once, caps150 apps, substitutes the package
name if an individual label fails, sorts resolved strings, and caches30s. Concurrent
reads join one pending query. A2.8s read wait returns apps_loading while the query
continues; later intentional read-only requests can obtain its result. No mutation
is automatically retried. Stop cancels/discards session results without waiting
on a loader-held lock. A stuck Android Binder may still finish later; no physical
phone performance guarantee is made.

Direct open-package now validates and resolves only the exact requested package,
without enumerating every installed app. This removes discovery as a prerequisite
for the known Bridge test target. Main-dispatch errors return specific safe codes;
read-only screen gets3.5s, mutations retain1.2s wait, client timeout remains5s.

Remote VoiceOutput was constructed without refresh/startEngine, unlike manual
MainActivity voice which had an onResume refresh.0.4.1 explicitly starts the remote
engine on creation/reload/fallback. Device state adds voice_status, voice_language,
app_catalog_state and last_dispatch_error. These allow the next phone result to
identify the actual state instead of guessing. Real TTS readiness/audio still
needs a phone listening test.

## Upgrade without reinstalling Hermes or its SDK

The existing0.4 adapter and19 tools are compatible. Only update the Bridge APK,
renew its session token, then restart the saved gateway launcher. Do not repeat
SDK installation, edit credentials, reset Telegram, or remove Termux/Ubuntu.

1. Ctrl+C the current foreground gateway; wait for native Termux `~ $`.
2. Install [verified0.4.1 APK](https://github.com/techwithrakibofficial/Hermes-Android-Bridge/releases/download/dev-15/Hermes-Bridge-0.4.1.apk).
   If a signing mismatch occurs, reinstall only Bridge and re-enable Accessibility.
3. In Bridge Start local bridge and enable Allow screen reading & control.
4. Copy its Termux pairing command, paste **alone** at native `$`, Enter.
5. Pair using the already-installed private runtime:

```sh
proot-distro login ubuntu -- env HERMES_BRIDGE_TOKEN="$HERMES_BRIDGE_TOKEN" /root/.local/share/hermes-android-bridge/mcp-env/bin/python /root/.local/share/hermes-android-bridge/bridge_mcp.py --pair
```

Only after `Android bridge paired` succeeds, restart:

```sh
proot-distro login ubuntu -- /root/.local/share/hermes-android-bridge/hermes-with-android gateway run
```

No new Termux session or adapter download needed. Keep copied token/.env private.
