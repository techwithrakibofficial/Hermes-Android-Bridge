#0.4.2 repair — snapshot freshness

## Observed phone evidence

0.4.1 catalog, device-state, package opening and read-only screen calls work in
user-supplied Telegram output. After the output-limit instructions a short reply
worked, Telegram screen returned25 nodes and Bridge screen returned41/44 nodes.
The safe button was offscreen. Three fresh snapshot+scroll attempts each failed
with stale_snapshot_observe_again. No actual scroll/click/type or Counter:1
success was established.

## Confirmed defect and bounded repair

0.4.1 rejected the snapshot on any content/window/text/scroll event across the
service, regardless of whether the active window or selected target changed.
The old generic error also covered wrong IDs/expiry; the actual cause on the
phone is not proven without more detailed data.

0.4.2 records events as hints and always rereads a bounded visible tree before a
UI mutation. It compares the current window/package, private SHA256 fingerprint
of observed visible content and exact Android node identity/properties. A matching
event storm alone does not reject unchanged state. Actual changed context
(including recipient/header text when it is in the observed subset), wrong node,
hidden/disabled/password control, unsupported action, wrong/expired snapshot,
locked phone or consumed lease is rejected with a specific code. Expiry remains
60s; every mutation consumes the lease and requires a new observation afterwards.

Fingerprints cover only the bounded observed subset, not all hidden/offscreen
content or every possible Android race. App-specific messaging/calling workflows
still need recipient and outcome checks. Password text/descriptions/children
remain omitted; other personal visible text may reach the configured model.

UI-node dispatch has3.5s total budget including validation; traversal checks its
deadline and a final check prevents starting a mutation if validation used its
time. An Android action already dispatched may still complete after a timeout,
so no blind action retry is allowed. Stop still clears session access/snapshots.

Open safe control test is now pinned above the scrollable setup content. Its
visibility no longer depends on how far down the settings screen was scrolled.
This also avoids repeated navigation/model requests just to reach a test target.

## Verification boundary

The local execution host disconnected during implementation. Changes are
persisted in GitHub; GitHub Actions runs compilation/lint and JVM fixtures.
The22 new guard assertions cover noise events with unchanged context, real context
and window/package changes, expiry, wrong/replaced IDs, one-use, node substitution,
hidden/disabled/password targets. They use fabricated states, not real TECNO nodes.
Existing46 protocol and22 app-catalog checks remain. Python adapter source is
unchanged; its prior61 tests on3.12/3.14 remain the adapter baseline.

Do not claim actual0.4.2 scrolling/clicking/typing until phone verification.

## Update and pair without changing Hermes

1. Ctrl+C current foreground gateway in Termux.
2. Install [verified0.4.2 APK](https://github.com/techwithrakibofficial/Hermes-Android-Bridge/releases/download/dev-16/Hermes-Bridge-0.4.2.apk).
3. Start the app bridge and enable screen control.
4. Copy the new pairing export, paste it alone into native Termux and Enter.
5. Run:

```sh
proot-distro login ubuntu -- env HERMES_BRIDGE_TOKEN="$HERMES_BRIDGE_TOKEN" /root/.local/share/hermes-android-bridge/mcp-env/bin/python /root/.local/share/hermes-android-bridge/bridge_mcp.py --pair
```

On Android bridge paired, run:

```sh
proot-distro login ubuntu -- /root/.local/share/hermes-android-bridge/hermes-with-android gateway run
```

Existing19-tool adapter, SDK, model/provider credentials, Telegram and memory
remain in use. Keep the saved model.max_tokens output cap. No new inference
provider, paid service, model upgrade or APK-independent SDK reinstall is needed.
